# API contract

## Allowed host and endpoints

The client accepts only the exact HTTPS Sandbox base URL
`https://ait-sandbox.qbench.net`. Redirects are rejected and TLS certificate
verification uses Python's default trusted certificate store.

## OAuth JWT-bearer exchange

The publisher loads the Client ID and Client Secret from `--secrets-file` and
uses them only in memory to create a short-lived HS256 JWT assertion. The exact
existing Sandbox API client's QBench-hosted `QBench API 2.0 OAS3` documentation
proves `POST /qbench/api/v2/auth/token` with `multipart/form-data`, fields
`assertion` and `grant_type`, and grant type
`urn:ietf:params:oauth:grant-type:jwt-bearer`. The response must be JSON with a nonblank
`access_token`, `token_type` equal to `Bearer`, and numeric `expires_in` from 1
through 3,600 seconds. The token is held only in memory. The exchange has a
timeout, no redirects, and no retry.

The earlier `/qbench/api/v1/oauth/token` request remains recorded as a
historical HTTP 404. Authoritative discovery proves that its path and request
body were incorrect; it does not prove invalid credentials. Operational
configuration now locks the authoritative relative token path while retaining
the single exact Sandbox origin.

Allowed operations:

```text
GET /qbench/api/v1/batch/{batch_id}
GET /qbench/api/v1/test/{test_id}
GET /qbench/api/v1/test/{test_id}/worksheet
PATCH /qbench/api/v1/test/{test_id}/worksheet
```

No other QBench path is generated by the client.

## GET Batch schema

The response must be a JSON object, optionally wrapped in `data`, containing:

- exact `id` or `batch_id` equal to the requested ID;
- nonblank `display_name` or `name`;
- `test_ids` array;
- nonblank `worksheet_id`;
- `worksheet_json` object or JSON string with `data` sheets and
  `qb_config.named_cells`.

IDs may be nonblank strings or native integers. Integer IDs are canonically
represented as base-10 strings; string IDs are never trimmed, case-folded, or
fuzzy-matched.

## GET Test schema

The response must provide an exact Test ID, Batch ID, Sample ID, assay ID,
assay name, workflow, worksheet ID, and worksheet JSON. The publisher rejects
missing identifying metadata. The returned Test ID, Batch membership, Sample,
assay, and workflow must all match the reviewed plan.

## PATCH payload

One request is sent for one exact Test:

```json
{
  "data": {
    "<approved_named_cell>": "<reviewed value>"
  },
  "qbench_update_reason":
    "Reviewed Terpenes Batch publish; source hash <12-character prefix>"
}
```

The complete request is prepared before submission. PATCH is attempted once
and never retried. The client suppresses response bodies and request URLs from
errors. A timeout after submission has an unknown outcome and triggers a GET
verification plus controlled-stop/rollback logic.

## Explicitly prohibited

- Test results or Pass/Fail endpoints;
- bulk Test updates;
- full worksheet replacement;
- Batch worksheet PATCH;
- database calls;
- browser session credentials;
- redirects to any alternate host;
- live QBench endpoints.

The authenticated API response shape and analyte PATCH representation still
require controlled Sandbox evidence before any PATCH.
